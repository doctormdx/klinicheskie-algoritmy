# Клинические алгоритмы — сайт для врачей

Сайт: https://algoritmvracha.ru · админка: https://algoritmvracha.ru/admin/

Статический сайт: 365 схем, 20 разделов, поиск по названиям, ключевым словам и сокращениям, фильтры «Тип» и «Пациенты». Новые схемы добавляются через админку в браузере. Сайт обновляется сам через 1–2 минуты после сохранения.

Схема работы:

```
Админка (/admin/) ──► репозиторий на GitHub ──► GitHub Actions собирает сайт ──► бакет Яндекс Облака ──► врачи
```

## Запуск (один раз, около часа)

### 1. GitHub: где хранится контент

Готово: проект загружен в приватный репозиторий [doctormdx/klinicheskie-algoritmy](https://github.com/doctormdx/klinicheskie-algoritmy), автопубликация уже подключена.

### 2. Яндекс Облако: где работает сайт

1. Зайдите в [console.yandex.cloud](https://console.yandex.cloud) и создайте платёжный аккаунт. Понадобится карта, но в пределах бесплатного объёма деньги не списываются: 1 ГБ хранения и 100 ГБ трафика в месяц. Сайт занимает около 65 МБ.
2. **Object Storage → Создать бакет.**
   - Имя: без точек, например `algoritmy-vracham`. Тогда сайт сразу откроется по адресу `https://algoritmy-vracham.website.yandexcloud.net`.
   - Если есть свой домен, назовите бакет точно как домен (см. шаг 5).
   - Доступ на чтение объектов и доступ к списку объектов: **Публичный**.
3. В бакете откройте **Веб-сайт → Хостинг**: главная страница `index.html`, страница ошибки `404.html`. Сохраните.
4. **Сервисные аккаунты → Создать**: имя `deploy`, роль `storage.editor`.
   Откройте этот аккаунт → **Создать новый ключ → Статический ключ доступа**. Сохраните *идентификатор ключа* и *секретный ключ*: секретный ключ показывается только один раз.

### 3. Связать GitHub с Яндекс Облаком

В репозитории на GitHub откройте **Settings → Secrets and variables → Actions**.

- Вкладка *Secrets* → *New repository secret*:
  - `YC_ACCESS_KEY_ID` — идентификатор ключа;
  - `YC_SECRET_ACCESS_KEY` — секретный ключ.
- Вкладка *Variables* → *New repository variable*:
  - `YC_BUCKET` — имя бакета.

Затем откройте **Actions → «Публикация сайта» → Run workflow**. Через 1–2 минуты сайт появится по адресу бакета.

### 4. Вход в админку

1. На GitHub откройте **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
   - Repository access: *Only select repositories* → ваш репозиторий.
   - Permissions → Repository permissions → **Contents: Read and write**.
   - Срок действия: 1 год. Когда срок истечёт, создайте новый токен.
2. Откройте `https://адрес-сайта/admin/` → **Войти с помощью токена доступа** → вставьте токен.

### 5. Свой домен (по желанию)

1. Купите домен у любого регистратора (reg.ru, nic.ru и т. п.).
2. Создайте бакет с именем, **точно совпадающим с доменом**, и настройте его как в шаге 2.
3. В DNS домена добавьте запись `CNAME` → `ваш-домен.website.yandexcloud.net`. Для домена второго уровня используйте `ANAME` в Cloud DNS Яндекса.
4. **Certificate Manager → Добавить сертификат → Let's Encrypt** для домена. Затем в бакете: **HTTPS → Certificate Manager** → выберите сертификат.
5. На GitHub поменяйте переменную `YC_BUCKET` на новое имя бакета. В админке, в разделе **Настройки сайта → Адрес сайта**, впишите `https://ваш-домен.ru`.

### 6. Яндекс Метрика

1. На [metrika.yandex.ru](https://metrika.yandex.ru) нажмите **Добавить счётчик** и укажите адрес сайта. Вебвизор можно включить.
2. Скопируйте номер счётчика (только цифры) и вставьте его в админке: **Настройки сайта → Номер счётчика Яндекс Метрики**.
3. В Метрике откройте **Цели → Добавить цель → JavaScript-событие**, идентификатор `search`. Так вы увидите, что ищут врачи.
   - Запросы видны в отчёте **Содержание → Параметры визитов**, в поле `search_query`.
   - Запросы, по которым ничего не нашлось, — в поле `not_found`. Это готовый список схем, которые стоит добавить.

> Метрика использует cookie. По закону о персональных данных (152-ФЗ) на сайте должны быть политика обработки персональных данных и уведомление о cookie.

## Как добавить новую схему

1. Откройте `/admin/` → **Схемы → Новая схема**.
2. Заполните поля:
   - название;
   - картинка: PNG или JPG, сжимается автоматически;
   - раздел;
   - тип;
   - пациенты;
   - ключевые слова и сокращения через запятую, например «ОРДС, ARDS». Это важно для поиска.
3. Нажмите **Сохранить**. Через 1–2 минуты схема появится на сайте, в поиске, в разделе и в списке «Все схемы».
   Ещё она появится в блоке **«Новые схемы»** на главной и на странице `/new/`, с отметкой «новое» на 30 дней. Дата добавления ставится автоматически — это время сохранения. Схемы исходного каталога новыми не считаются.

Там же можно исправить или удалить схему, добавить новый раздел (**Разделы**) и изменить название сайта (**Настройки сайта**).

## Как добавить новость

1. Откройте `/admin/` → **Новости → Новая новость**.
2. Заполните поля:
   - заголовок;
   - дата: сегодняшняя ставится сама;
   - **специальность**: те же разделы, что у схем. Если новость важна для нескольких специальностей, добавьте их в «Дополнительные специальности»;
   - **тематика**: список можно пополнять в **Тематики новостей**;
   - краткий анонс: 1–2 предложения, показывается в списке новостей;
   - текст: можно выделять жирным, делать списки, вставлять картинки;
   - ссылка на первоисточник и его название;
   - картинка: необязательно.
3. Нажмите **Сохранить**. Через 1–2 минуты новость появится:
   - на странице `/news/`, где есть фильтры по специальности и тематике;
   - в блоке «Новости» на странице раздела этой специальности.

   Ссылка «Новости» в шапке сайта появляется после первой новости. На странице новости сайт сам подбирает «Схемы по теме» из той же специальности — по словам из заголовка, анонса и текста.

> Пересказывайте новости своими словами и ставьте ссылку на первоисточник. Не копируйте статьи и картинки из журналов.

> Одна схема, «Диагностика лёгочной гипертензии при ХОБЛ или интерстициальном заболевании лёгких», пока без картинки: файл не передался из-за очень длинного имени. Откройте её в админке и загрузите картинку. До этого она на сайте не показывается.

## Автоматические новости из DynaMed

```
DynaMed ──(2 раза в день)──► GitHub Actions: вход, новые алерты, перевод и разметка моделью
                                   │
                                   ▼
                     черновики в админке (на сайте не видны)
                                   │
                                   ▼
             вам в Telegram: «Опубликовать» · «Отклонить» · «Исправить в админке»
                                   │ Опубликовать
                                   ▼
        сайт обновляется ──► пост в канал + подписчикам бота по специальностям
                                         + пуш-уведомления в браузере по специальностям
```

- Сбор идёт в 9:17 и 18:17 по Москве, за раз — не больше 10 новых алертов.
- Модель делает из алерта и подробностей со страницы темы DynaMed новость на русском: заголовок, анонс, текст, пост для Telegram, специальность и тематику из списков сайта. Ссылка на первоисточник (DOI статьи, FDA, EMA) ставится на сайт; ссылка на DynaMed видна только в админке, в поле «Оригинал».
- Опубликовать можно и в админке: откройте новость (фильтр «На проверке»), поправьте текст, поставьте статус «Опубликовано», сохраните. Рассылка уйдёт так же.
- Врачи подписываются на странице «Новости»: через бота (выбирают специальности кнопками) или на уведомления в браузере. На iPhone уведомления в браузере работают, только если сайт добавлен на экран «Домой».

### Настройка (один раз)

**1. Telegram.** В [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен бота. Создайте канал для новостей и добавьте бота в администраторы с правом публиковать сообщения.

**2. Модель для перевода.** Подойдёт один из вариантов:
- **Claude API** — ключ в [console.anthropic.com](https://console.anthropic.com). Anthropic не обслуживает аккаунты из России.
- **YandexGPT** — [Yandex AI Studio](https://aistudio.yandex.ru): сервисный аккаунт с ролью `ai.languageModels.user` → API-ключ. В переменных GitHub укажите `LLM_PROVIDER` = `openai` и `LLM_MODEL` = `gpt://<ID каталога>/yandexgpt/latest`.
- Любой другой OpenAI-совместимый API: `LLM_PROVIDER` = `openai`, `LLM_BASE_URL` — адрес API, `LLM_MODEL` — модель.

**3. Яндекс Облако.** Сервисному аккаунту `deploy` добавьте роль `functions.admin` (роль `storage.editor` у него уже есть). В этом аккаунте: **Создать новый ключ → Авторизованный ключ** → скачайте JSON-файл. Ещё понадобится ID каталога: он виден в консоли рядом с названием каталога.

**4. GitHub: Settings → Secrets and variables → Actions.**

| Где | Имя | Что вписать |
|---|---|---|
| Secrets | `DYNAMED_LOGIN`, `DYNAMED_PASSWORD` | логин и пароль DynaMed |
| Secrets | `LLM_API_KEY` | ключ модели из шага 2 |
| Secrets | `TELEGRAM_BOT_TOKEN` | токен бота |
| Secrets | `NEWS_API_SECRET` | придумайте код из 30+ латинских букв и цифр, без пробелов и запятых |
| Secrets | `GH_PAT` | токен GitHub из шага «Вход в админку» (права Contents: Read and write) — им бот публикует новости |
| Secrets | `YC_SA_KEY` | всё содержимое JSON-файла из шага 3 |
| Variables | `YC_FOLDER_ID` | ID каталога Яндекс Облака |
| Variables | `TELEGRAM_CHANNEL` | имя канала с @, например `@algoritmvracha_news` |

**5. Запустите бота:** Actions → **«Бот новостей»** → Run workflow. Функция создастся в Яндекс Облаке, вместе с закрытым бакетом для подписок; её адрес сам пропишется в настройки сайта.

**6. Назначьте себя модератором:** напишите боту `/admin ваш-NEWS_API_SECRET`. Черновики будут приходить в этот чат.

**7. В админке → Настройки сайта** впишите «Бот в Telegram» (имя без @) и «Канал в Telegram» (ссылку). На странице «Новости» появится блок подписки.

**8. Проверьте сбор:** Actions → **«Сбор новостей»** → Run workflow с галочкой «Только проверить вход». Если вход не удался, снимок экрана лежит в артефакте `debug` этого запуска. Потом запустите без галочки — черновики придут в Telegram.

Необязательные переменные: `NEWS_MAX_PER_RUN` — сколько алертов обрабатывать за раз (по умолчанию 10); `NEWS_AUTO_PUBLISH` = `true` — публиковать сразу, без проверки; `YC_DATA_BUCKET` — имя бакета для подписок (по умолчанию `algoritmvracha-news-data`).

> Материалы DynaMed — платный контент по лицензии. На сайт и в Telegram попадает пересказ со ссылкой на первоисточник, а не копия. Условия вашей подписки DynaMed всё равно стоит проверить.

## Для разработчика

```
content/schemes/*.json   схемы (одна схема — один файл)
content/sections/*.json  разделы
content/images/          картинки схем (WebP)
content/settings.json    название сайта, адрес, номер Метрики
src/build.mjs            сборка: страницы, сжатие картинок, поисковый индекс
src/templates.mjs        HTML-шаблоны
src/assets/              стили и скрипт поиска
admin/config.yml         поля админки (Sveltia CMS)
tools/import_catalog.py  массовый импорт из CSV-каталога
tools/news/              сбор новостей DynaMed: вход (dynamed.mjs), перевод (ai.mjs), запуск (collect.mjs)
functions/news-bot/      функция Яндекс Облака: Telegram-бот, модерация, рассылка, пуш-подписки
data/news-seen.json      какие алерты DynaMed уже обработаны
```

Новость со `"status": "draft"` на сайт не попадает. Сборка публикует `/news.json` и `/specs.json` — по ним функция рассылает новые новости после каждой выкладки (шаг «Рассылка новостей» в `deploy.yml`).

Локально: `npm ci && npm run build && npm run preview` → http://localhost:4321

Сайт не использует Cloudflare, Vercel, Netlify и шрифты с внешних CDN: всё загружается из бакета в Яндекс Облаке. Главная страница передаётся за ~8 КБ, страница со схемой — за ~130 КБ.
